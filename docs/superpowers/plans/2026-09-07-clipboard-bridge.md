# Clipboard Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ctrl+v in Claude Code inside remote tmux paste the mac clipboard image, and stop the tmux `y` binding from piping to a pbcopy that does not exist on Linux.

**Architecture:** Pull on demand over a reverse ssh forward. A socket-activated launchd agent on the mac answers `types` and `png` requests from the pasteboard; the mac's ssh config forwards `127.0.0.1:2224` into every `*.exe.xyz` session; a `wl-paste` shim on the VM answers the two calls Claude Code makes by asking that port. VM-to-mac text stays OSC 52 through kitty and is untouched.

**Tech Stack:** bash (3.2-compatible on the mac side), launchd socket activation, OpenSSH `RemoteForward` + `ControlMaster`, `osascript` / `sips`, tmux `if-shell`, python3 for test fixtures and fake servers.

**Spec:** `docs/superpowers/specs/2026-09-07-clipboard-bridge-design.md` (this repo, this branch). Spec PR: nonreagent/dotfiles#18.

Create `overlay/bin/wl-paste`:

```bash
#!/usr/bin/env bash
# wl-paste shim: the VM half of the clipboard bridge.
#
# There is no Wayland on this VM, so nothing real is shadowed. Claude Code's
# ctrl+v image paste on Linux tries xclip (fails here: no display) and then
# falls back to exactly two wl-paste calls: `-l` to list clipboard types and
# `--type image/png` to fetch the bytes. This answers both by asking the mac
# through the port its ssh config reverse-forwards into every *.exe.xyz session
# (nonrational/dotfiles: home/.ssh/config.d/exe.conf). The mac side serves
# images only, and only while a session is connected; otherwise the connect is
# refused and ctrl+v is a quiet no-op. Everything else, text reads included,
# exits 1 so Claude Code moves on to its next backend.
#
# Design: docs/superpowers/specs/2026-09-07-clipboard-bridge-design.md
set -u
port="${CLIPBOARD_BRIDGE_PORT:-2224}"

# One request line out, raw response in, until the mac closes the connection.
# The braces keep a refused connect off stderr without redirecting the shell's
# stderr for good (a bare `exec` with only redirections would).
request() {
  { exec 3<>"/dev/tcp/127.0.0.1/$port"; } 2>/dev/null || return 1
  printf '%s\n' "$1" >&3
  # A listener whose ssh session died (mac asleep) accepts and then hangs
  # while sshd fails to open the channel; cap that so ctrl+v stays a no-op.
  timeout 10 cat <&3
}

case " $* " in
  *" -l "* | *" --list-types "*)                request types ;;
  *" --type image/png "* | *" -t image/png "*)  request png ;;
  *)                                            exit 1 ;;
esac
```

Then: `chmod +x overlay/bin/wl-paste`

```bash
# docs/superpowers/specs/2026-09-07-clipboard-bridge-design.md). The pasteboard

args="$*"

# bridge <clipboard-mode> <stdin-bytes>: run the script the way launchd does
# (request on stdin, response on stdout). Captures stdout in $OUT, exit in $status.
bridge() {
  set +e
  printf '%s' "$2" | FAKE_CLIPBOARD="$1" FAKE_FIXTURE="$FIXTURE" FAKE_LOG="$LOG" \
    PATH="$FAKEBIN:$PATH" TMPDIR="$BASE/tmp" "$BRIDGE" > "$OUT"
  status=$?
  set -e
}

}

    ok "types reports image/png for a PNG pasteboard"
  else
    bad "types reports image/png for a PNG pasteboard (status=$status out=$(cat "$OUT"))"
  fi
}

test_types_reports_png_for_tiff_only() {

}

  else

  fi
}
```

```bash
#!/usr/bin/env bash
# clipboard-bridge: hand the mac clipboard IMAGE to one connection, then exit.
#
# launchd runs this per connection (org.nonrational.clipboard-bridge.plist,
# inetd-style) with the accepted socket on stdin, stdout and stderr. The peer
# is an exe.dev VM: its wl-paste shim reaches 127.0.0.1:2224 through the
# RemoteForward in ~/.ssh/config.d/exe.conf, turning Claude Code's ctrl+v into
# the two requests below. Design and trust model live in nonreagent/dotfiles,
# docs/superpowers/specs/2026-09-07-clipboard-bridge-design.md.
#
# Protocol: the client sends one line.
#   types -> "image/png\n" when the pasteboard holds image data, else nothing (exit 0)
#   png   -> raw PNG bytes (no image: nothing, exit 1)
# Anything else: nothing, exit 1. There is deliberately no write path and no
# text path: a VM process can read an image the user just copied, nothing else.
#
# Runs under /bin/bash 3.2: launchd's PATH is /usr/bin:/bin:/usr/sbin:/sbin.
set -u

# In inetd mode stderr IS the socket; a stray diagnostic would land inside the
# PNG stream. Diagnostics go to syslog instead: `log stream --info --predicate
# 'process == "logger"'`, or Console.app, tag clipboard-bridge.
exec 2>/dev/null
log() { logger -t clipboard-bridge -- "$*"; }

# `clipboard info` lists every flavour on the pasteboard, e.g.
# {{«class PNGf», 12345}, {«class TIFF», 67890}}. Screenshots carry both;
# copies from Preview carry TIFF (and PDF). Either is enough for write_png.
# A failed read (a permission denial, say) is logged rather than passed off
# as "no image", so the troubleshooting steps can tell the two apart.
has_image() {
  local info
  info="$(osascript -e 'clipboard info' 2>&1)" \
    || { log "clipboard info failed: ${info:0:200}"; return 1; }
  grep -qE 'PNGf|TIFF' <<<"$info"
}

# Write the pasteboard image to $1 as PNG. Same coercion Claude Code uses on
# macOS; the TIFF fallback covers Preview-style copies, converted by sips.
# stdout is the wire, so every helper's stdout is discarded.
write_png() {
  if osascript -e 'set d to (the clipboard as «class PNGf»)' \
      -e "set f to open for access POSIX file \"$1\" with write permission" \
      -e 'write d to f' -e 'close access f' >/dev/null; then
    return 0
  fi
  osascript -e 'set d to (the clipboard as «class TIFF»)' \
    -e "set f to open for access POSIX file \"$1\" with write permission" \
    -e 'write d to f' -e 'close access f' >/dev/null \
    && sips -s format png "$1" --out "$1.png" >/dev/null \
    && mv -f "$1.png" "$1"
}

verb=""
IFS= read -r -t "${CLIPBOARD_BRIDGE_READ_TIMEOUT:-5}" verb || { log "no request received"; exit 1; }
verb="${verb%$'\r'}"

case "$verb" in
  types)
    has_image && printf 'image/png\n'
    exit 0
    ;;
  png)
    tmp="$(mktemp "${TMPDIR:-/tmp}/clipboard-bridge.XXXXXX")" || exit 1
    trap 'rm -f "$tmp" "$tmp.png"' EXIT
    if write_png "$tmp" && [ -s "$tmp" ]; then
      cat "$tmp"
      exit 0
    fi
    log "png requested but the pasteboard holds no image"
    exit 1
    ;;
  *)
    log "unknown request: ${verb:0:40}"
    exit 1
    ;;
esac
```

```bash
#!/bin/bash
# Smoke tests for home/.tmux.conf: the file loads in a throwaway server, and the
# copy-mode `y` binding follows pbcopy availability (pipe through pbcopy where
# it exists, plain copy plus the terminal's OSC 52 elsewhere). Each case starts
# its own tmux server on a private socket under a fake HOME, so nothing here
# touches a live session. PATH is set per case, and tmux is invoked by absolute
# path because bash resolves a command with the temporarily assigned PATH.
set -euf -o pipefail

ROOT="$(cd "$(dirname "$0")/.." && pwd)"
CONF="$ROOT/home/.tmux.conf"
BASE="$(mktemp -d "${TMPDIR:-/tmp}/test-tmux.XXXXXX")"
BASE="$(cd "$BASE" && pwd)"
trap 'rm -rf "$BASE"' EXIT

pass=0
fail=0
ok()   { pass=$((pass + 1)); echo "PASS: $1"; }
bad()  { fail=$((fail + 1)); echo "FAIL: $1"; }
skip() { echo "SKIP: $1"; }

if ! command -v tmux >/dev/null 2>&1; then
  skip "tmux smoke tests (tmux not installed)"
  echo "0 passed, 0 failed"
  exit 0
fi
TMUX_BIN="$(command -v tmux)"

FAKEHOME="$BASE/home"
mkdir -p "$FAKEHOME" "$BASE/nobin" "$BASE/pbcopybin"
printf '#!/bin/sh\ncat >/dev/null\n' > "$BASE/pbcopybin/pbcopy"
chmod +x "$BASE/pbcopybin/pbcopy"

# y_binding <PATH>: load the config in a fresh server with that PATH, print the
# copy-mode-vi binding for y, stop the server. Output lands in $got, exit in $status.
# TMUX_TMPDIR keeps the socket under $BASE, so the EXIT trap removes it even
# where tmux leaves the dead socket file behind after kill-server.
y_binding() {
  local sock="tmuxtest-$$-$RANDOM"
  set +e
  got="$(HOME="$FAKEHOME" SHELL=/bin/sh PATH="$1" TMUX_TMPDIR="$BASE" "$TMUX_BIN" -L "$sock" -f "$CONF" start-server \; list-keys -T copy-mode-vi y 2>&1)"
  status=$?
  set -e
  TMUX_TMPDIR="$BASE" "$TMUX_BIN" -L "$sock" kill-server 2>/dev/null || true
}

test_config_loads() {
  y_binding "$BASE/nobin"
  if [ "$status" = 0 ] && [ -n "$got" ] && ! grep -qiE 'unknown|error|invalid' <<<"$got"; then
    ok ".tmux.conf loads without errors"
  else
    bad ".tmux.conf loads without errors (status=$status: $got)"
  fi
}

test_y_pipes_to_pbcopy_when_present() {
  y_binding "$BASE/pbcopybin"
  if grep -q 'copy-pipe-and-cancel pbcopy' <<<"$got"; then
    ok "y pipes through pbcopy when pbcopy is on PATH"
  else
    bad "y pipes through pbcopy when pbcopy is on PATH (got: $got)"
  fi
}

test_y_plain_copy_without_pbcopy() {
  y_binding "$BASE/nobin"
  if grep -q 'copy-selection-and-cancel' <<<"$got" && ! grep -q pbcopy <<<"$got"; then
    ok "y is a plain copy-selection-and-cancel without pbcopy"
  else
    bad "y is a plain copy-selection-and-cancel without pbcopy (got: $got)"
  fi
}

test_config_loads
test_y_pipes_to_pbcopy_when_present
test_y_plain_copy_without_pbcopy

echo "----"
echo "$pass passed, $fail failed"
[ "$fail" -eq 0 ]
```

```bash
gh pr create --base main --head clipboard-bridge --reviewer nonrational \
  --title "Serve clipboard images to exe.dev VMs over a reverse ssh forward" \
  --body "$(cat <<'EOF'
### Problem

An image on the mac clipboard cannot be pasted into Claude Code running inside tmux on an exe.dev VM. Claude Code on Linux shells out to `xclip`/`wl-paste`, the VM has no display server, and tmux swallows the replies of every in-band terminal clipboard protocol. Separately, the tmux `y` binding pipes to `pbcopy` on every host, which fails silently on Linux.

### Motivation

Agent sessions run remotely in tmux, and a screenshot is the fastest way to show Claude a UI problem. Today that means scp games. exe.dev's gateway was verified to relay reverse ssh forwards, which opens a clean out-of-band path. Design, probes, and the clipfan evaluation: `docs/superpowers/specs/2026-09-07-clipboard-bridge-design.md` in nonreagent/dotfiles#18 (on `main` there once that PR merges).

### Proposed Solution

Four commits, each independently testable:

- `home/bin.Darwin/clipboard-bridge`: a bash responder that answers `types` and `png` from the pasteboard via `osascript` (TIFF + `sips` fallback) and refuses everything else. No write path, no text path. Tested with stubbed `osascript`/`sips`/`logger` so the suite runs on Linux CI too.
- `home/Library/LaunchAgents/org.nonrational.clipboard-bridge.plist`: socket-activated, inetd-style, on `127.0.0.1:2224`; nothing runs while idle. Deployed via a Darwin manifest row; `make clipboard-bridge` bootstraps or reloads it.
- `home/.ssh/config.d/exe.conf`: `RemoteForward 127.0.0.1:2224` for `*.exe.xyz`, plus `ControlMaster`/`ControlPersist` so windows share one connection and the forward is requested once, plus keepalives. One-time: `Include config.d/*.conf` at the top of `~/.ssh/config`.
- `home/.tmux.conf`: `y` pipes to pbcopy only where pbcopy exists; elsewhere the plain copy binding stands and OSC 52 does the rest. `test/test_tmux.sh` loads the config in a scratch server under both PATHs.

The VM half (a `wl-paste` shim) lands in nonreagent/dotfiles#18.

### Feedback

- **Trust tradeoff.** While a session is connected, and for up to four hours after the last window closes (`ControlPersist 4h` keeps the master and its forward alive; `ssh -O exit <vm>.exe.xyz` ends it early, and a shorter `ControlPersist` shrinks the tail), any VM process can read the mac clipboard **image** on demand. Text is never served and the bridge has no write path.
- **ssh behaviour change.** `ControlMaster auto` + `ControlPersist 4h` for every `*.exe.xyz` host is more than the forward: shared connections, a background master for four hours after the last window closes. Comfortable with that?
- **First-run checks on the mac.** Two things could only be verified on macOS: Sequoia's pasteboard privacy prompt for `osascript` under launchd (Claude Code uses the same call; allow once if asked), and `launchctl bootstrap` on a symlinked plist. `make clipboard-bridge` prints a confirmation line when the agent loads; if `bootstrap` right after `bootout` ever returns `Bootstrap failed: 5: Input/output error`, run it again (or put a `sleep 1` between the two), and `launchctl print gui/$(id -u)/org.nonrational.clipboard-bridge` is the richer status view. A failed pasteboard read is logged as `clipboard info failed: ...` under the `clipboard-bridge` tag, distinct from a text-only clipboard, which logs nothing.
- **Manual verification after `make deploy && make clipboard-bridge`:** with an image on the clipboard, `printf 'types\n' | nc 127.0.0.1 2224` prints `image/png` and `printf 'png\n' | nc 127.0.0.1 2224 | file -` reports PNG image data.
EOF
)"
```
